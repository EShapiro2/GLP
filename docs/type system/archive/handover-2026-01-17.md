### Part 2: Bug 1 Fix - Atoms as Strings

**Issue:** Atoms like `user`, `net`, `foo` not matching `Constant?` type

**Root cause:** In `well_typed_term.dart`, function `_pathStepToLeafTerm` line ~295-300, unquoted atoms were treated as generic constants instead of strings.

**Paper reference:** Section 4.1, line 49: `String ::= ... ; a ; b ; ... ; foo ; bar ; ...`

**Fix applied:**
```dart
// OLD (line ~298):
return LeafTerm.constant(value, mode: step.mode);

// NEW:
// Fix Bug 1: Atoms (unquoted identifiers) are strings per paper Section 4.1
// Paper line 49: "String ::= ... ; a ; b ; ... ; foo ; bar ; ..."
// Therefore atoms like 'user', 'net', 'foo' etc. are strings
return LeafTerm.stringConstant(value, mode: step.mode);
```

**File:** `/Users/udi/Grassroots/GLP/glp_runtime/lib/analysis/type_checker/well_typed_term.dart`

**Status:** ✅ VERIFIED FIXED - All "user not matching Constant?" errors gone

### Bug 5: Assignment Mode Mismatch

**Error:**
```
Variable mode mismatch at wildcard _?
Path: ([|]/2, 0, input) → (Out1, 2, input)

Variable pair (Out, Out?) not complementary across clause: 
Variables across head/body must have same type: _ (base: _) != Stream? (base: Stream)
```

**Clause:**
```glp
lookup_send(Key, Msg, [(K, Out)|Rest], [(K?, Out1?)|Rest?], found) :-
    Key? =?= K? |
    Out = [Msg?|Out1].
```

**Context:**
- `FriendEntry ::= (Constant?, Stream)`
- Head: `(K, Out)` at FriendEntry position → `Out` is writer for `Stream`
- Head: `(K?, Out1?)` at FriendEntry output → `Out1?` is reader
- Body: `Out = [Msg?|Out1]` assigns list with `Out1` as tail

**Issue:** This is valid SRSW but type checker rejects it. Need to understand:
1. Why is `Out1` getting type `_?` instead of `Stream`?
2. Why does assignment `Out = [Msg?|Out1]` fail type checking?

**Spec reference:** Assignment handling in clause validation
