The proc decls committed in step 2.4d have **wrong Channel arity**. `Channel(In, Out)` takes 2 params but `send`/`receive` provide only 1:

**send** — currently `procedure send(X?, Channel(Stream(X))?, Channel(Stream(X))).`

**receive** — currently `procedure receive(X, Channel(Stream(X))?, Channel(Stream(X))).`

Should be: `procedure =..(_, Stream(_)?).`

**..=** — currently `procedure ..=(Stream, _?).`

### 2. Fix a bug in `param_expansion.dart`

When expanding parameterized types, the expanded type definitions are not post-processed through `_replaceParamRefs`. This means nested template references in expanded bodies retain their raw `TypeRef` names (e.g., `Stream` instead of `Stream<Msg>`) and fail lookup after monomorphic types are removed.

**Fix**: In `expandParameterizedTypes()`, after generating expanded type defs in the worklist loop, post-process each expanded def's alternatives through `_replaceParamRefs` before adding to the output. The fix is approximately:

In the main worklist loop, after building `newAlts`, add:
```dart
final processedAlts = newAlts
    .map((alt) => _replaceParamRefs(alt, templates, monoNames: monoNames))
    .toList();
expandedDefs.add(TypeDef(expandedName, processedAlts, template.line, template.column));
```

instead of:
```dart
expandedDefs.add(TypeDef(expandedName, newAlts, template.line, template.column));
```

This must also be done for the second worklist loop (which handles instantiations generated by wildcard substitution).
