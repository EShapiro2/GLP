# Bug Fixes: Three Integration Test Failures (2026-02-10)

**Date**: 2026-02-10
**Status**: Fixed
**Tests fixed**: `send_reader_boot.glp`, `three_agent_pipeline_boot.glp`

---

## Bug 1: `wait()` timer callback doesn't clean up suspended map

**File**: `glp_runtime/lib/bytecode/runner.dart` (line ~4865)
**Test**: `send_reader`

### Symptom

Agent1 finishes all goals but never reports "All goals completed". The test times out.

### Root Cause

The `wait/1` guard implementation creates a Dart `Timer` that binds a writer when it fires. The timer callback was using `cx.rt.gq.enqueue(goalRef)` to re-enqueue the reactivated goal. This re-enqueues the goal correctly but does not remove the stale entry from `runtime.suspended`. The completion check (`allCompleted`) requires `runtime.suspended.isEmpty`, so the agent appears to still have suspended goals.

### Fix

Changed `cx.rt.gq.enqueue(goalRef)` to `cx.rt.enqueueReactivatedGoal(goalRef)`, which calls `_removeFromSuspended(goal)` before enqueuing.

## Bug 2: Newly spawned gs goals missing `heap.onBind` callbacks

**File**: `glp_runtime/lib/multiagent/mad_context.dart` (in `_fireGlobalSendGoalIfExists`)
**Test**: `three_agent_pipeline`

### Symptom

When a `global_send` goal fires on a value containing nested variables, new gs goals are spawned for those variables. The new goals are registered in `GlobalSendRegistry` but never fire, so the nested values are never sent to the remote agent.

### Root Cause

`_fireGlobalSendGoalIfExists()` registers new goals in `GlobalSendRegistry` but did not set up `heap.onBind` callbacks. This is the same bug pattern as the earlier `registerGlobalSendSpawns` bug (documented in `bug-missing-onBind-in-receive-2026-02-09.md`): every gs goal registration must be paired with an `onBind` callback.

### Fix

Added `runtime.heap.onBind(newGoal.readerAddr, ...)` for each new goal in `_fireGlobalSendGoalIfExists()`.

## Bug 3: Value not globalized before serialization in gs firing

**File**: `glp_runtime/lib/multiagent/mad_context.dart` (in `_fireGlobalSendGoalIfExists`), `glp_runtime/lib/multiagent/global_send.dart` (`GlobalSendFiredResult`)
**Test**: `three_agent_pipeline`

### Symptom

Agent3 receives an assignment message for `_r(agent2, 2)` but throws: `Bad state: No LocalizeEntry for _r(agent2, 2)`. The receiver cannot handle nested global names in the value.

### Root Cause

`_fireGlobalSendGoalIfExists()` was passing the raw `result.value` (containing local VarRefs) to `createGlobalSendPayload`. The serializer serializes VarRefs as `(creator, localId)` pairs, but the receiver deserializes them back as VarRefs, not as GlobalNames. Without GlobalNames in the serialized form, the receiver has no way to create the LocalizeEntries needed to handle nested variables.

The `send()` method correctly calls `globalizeTermWithResult()` to substitute GlobalNames for VarRefs before serializing. `_fireGlobalSendGoalIfExists()` was missing this step.

### Fix

1. Added `extractedVariables` and `globalizeResult` fields to `GlobalSendFiredResult` (in `global_send.dart`).
2. `onWriterBound()` now returns these fields alongside the value.
3. `_fireGlobalSendGoalIfExists()` calls `globalizeTermWithResult()` to substitute GlobalNames before serializing.
