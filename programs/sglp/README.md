# sglp

sGLP's directory (Coordination Appendix B; renamed from svglp 2026-10-01): sGLP in GLP, as the stochastic pi-calculus was in FCP, written from sGLP's paper (the repository svGLP-Stochastic-Volitional-GLP at d2f64b6, Section 4) with nothing in the engine, the compiler or the checker.  The simulations written for sGLP's engine extension were removed with it on 2026-10-02 (git holds them, before that date).

A program rooted here: load `programs/sglp` and call its entry point.

- `self.glp` --- the directory: exposes `monitor.glp` and `construct.glp` to the subtree; the type of an sGLP source in the term form, `SglpTerms`; the entry points of the transformation, `transform(Program, Part)` and `transform_terms(V, S, Part)`; the horizon's units (`span/2`); `one_of`, `length` and `nth`, shared by the examples' profiles; the entry points `social_graph(Agents, Count, Unit, Seed)`, with the run declaration's mix, read from the printed `declaration/6`, and `social_graph(Agents, Count, Unit, Seed, Hom, Wary)`, with the mix given by two integers 0..100: an agent is homophile for its first draw K =< Hom and wary for its second K =< Wary, K of 1..100, so `social_graph/4` is `social_graph/6` at 60 and 70; and `social_graph_draw(Agents, Seed, Hom, Wary, D)`, the population's draw of that run without running it, `D = draw(Homophile, Indifferent, Wary, Sociable, As)`, `As` the list of `agent(A, Approach, Response)`, each agent's profiles, A of 1..Agents in order; and `coins(Agents, Friends, Count, Unit, Seed, Spend, Cred)`, coins among friends' run, agent a's friends the a-th list of Friends, the mix given by two integers 0..100: an agent is a spender for its first draw K =< Spend and cautious for its second K =< Cred, so the run declaration's is 50 and 50; and `coins_draw(Agents, Seed, Spend, Cred, D)`, that run's population's draw without running it, `D = draw(Spender, Saver, Generous, Cautious, As)`, `As` the list of `agent(A, Spending, Credit)`, A of 1..Agents in order, the draw not depending on the friends.

## The term form

sGLP's paper prints sGLP in its surface syntax, which GLP's reader does not read: `person p.`, `T =::= p.`, the run declaration and `G @ r` are not GLP terms, and GLP has no reader a program can call.  The transformation therefore reads an sGLP program in a term form, one GLP term per declaration and clause, in GLP-Spec's term syntax and nothing else (Definition "Logic Programs Syntax": a variable, a constant, a compound term `f(T1, ..., Tn)`, and the list notation), with no operator, as Jurix's contracts are written (`programs/jurix/contracts.glp`).  The paper's syntax is the surface form of this term form (Udi, 2026-10-03, to Integration Code: "term form (readable surface syntax can be used in papers even uf not identical to actual syntax)").  A source is a unit clause `source(V, S)`: `V` the vGLP program's interface, its types and its volitional procedure declarations, which the transformation reads for the person process; `S` the sGLP program, its items in order.  The two sources are `social_graph/graph_sglp.glp` and `coins/coins_sglp.glp`.

| Surface (the paper) | Term form | Example |
|---|---|---|
| `person p.` | `person(p)` | `person(homophile)` |
| `T =::= p.` | `binds('T', p)` | `binds('Menu', homophile_menu)` |
| `procedure p(T1, ..., Tn).` | `decl(p(T1, ..., Tn))` | `decl(homophile_menu(dual('Menu'), dual('Integer')))` |
| a type `T`, `T?` | `'T'`, `dual('T')` | `dual('Integer')` for `Integer?` |
| `H.` | `clause(H, [], [])` | `clause(issuer(holding(var('F'), var('_')), var('F?')), [], [])` |
| `H :- B1, ..., Bm.` | `clause(H, [], [B1, ..., Bm])` | `clause(spender_menu(var('M'), var('S')), [], [rated(request(var('S?'), var('M?')), rate(1, day))])` |
| `H :- G1, ..., Gk \| B1, ..., Bm.` | `clause(H, [G1, ..., Gk], [B1, ..., Bm])` | `clause(wary_answer(var('K'), card(var('_'), yes)), ['=<'(var('K?'), 20)], [true])` |
| a variable `X`, `X?`, `_` | `var('X')`, `var('X?')`, `var('_')` | `random(var('S?'), 100, var('K'), var('S1'))` |
| `X? =< 98`, an operator's term | the term itself, its functor quoted | `'=<'(var('K?'), 98)` |
| `G @ n/u` | `rated(G, rate(n, u))` | `rated(wary_answer(var('K?'), var('C?')), rate(1, day))` |
| `run n agents [d1 ~ (q1 : x1 ; ...), ...] until c u seed s.` | `run(n, [mix(d1, [share(q1, x1), ...]), ...], c, u, s)` | `run(100, [mix(approach, [share(homophile, 0.6), share(indifferent, 0.4)]), mix(response, [share(wary, 0.7), share(sociable, 0.3)])], 1, year, 20260927)` |
| `T ::= A1 ; ... ; Ak.` (the interface) | `type('T', [A1, ..., Ak])` | `type('Menu', [menu('Peers', 'Peers', dual('Choice'))])` |
| `procedure (T)*p(...).`, `(T?)*p(...)` (the interface) | `volitional('T', p(...))`, `volitional(dual('T'), p(...))` | `volitional('Menu', ask(dual('Peers'), dual('Peers'), 'Choice'))` |

The choices, where sGLP's suggestion of 2026-10-03 10:59 UTC used an operator or left the shape open:

  1. A source variable is data, `var(Text)`, never a GLP variable, so the unit clause holding a source satisfies SRSW; its text carries the reader's `?`, `var('K?')`, being printed as one token.
  2. `clause(H, Guards, Body)` in place of `(H :- G | B)`, and `mix(D, [share(Q, X), ...])` in place of `D ~ [(Q, X), ...]`: `:-`, `|`, `~` and `,` between terms are operators, which a term of GLP-Spec's syntax does not have.
  3. `rate(N, U)` in place of `N/U`, and `rated(G, rate(N, U))` for `G @ r`, `/` and `@` being operators.
  4. An operator's term in a guard or a body is the compound term it denotes, its functor quoted: `'=<'(var('K?'), 98)` is `K? =< 98`.
  5. A type `T?` is `dual('T')`: the transformation computes with the complement --- which argument of an interactive type is the answer, and whether a person procedure has the dual of its type (Section 3, Definition "Dual, ...").
  6. A procedure declaration is `decl(p(T1, ..., Tn))`, of the procedure's name and its argument types, `exported` and `procedure` being keywords of GLP's syntax and not terms.
  7. The interface `V` is the vGLP program's types, `type/2`, and its volitional procedure declarations, `volitional/2`; the transformation reads the interactive types from it, each of one compound alternative, and prints the person process from them.  The vGLP program's clauses are not in the source: vGLP's compilation is vGLP's (`graph.glp`, `coins.glp`).

What the transformation prints, and its choices:

  1. The profiles, `profiles.glp`: each item of the source in its order, a profile's `person` and `binds` as comment lines; Section 4's transformation of the clauses, `Token?` first for a procedure a rated goal calls, `MutualRef?` last for one that takes the monitor's reference, `exported` for a person procedure, which the person process calls from the module beside.  The monitor's reference is named `Mon` and the tokens `Tok`, `Tok1`, ..., the first not written in the clause.
  2. The population, `population.glp`: the stochastic person's type `Profiles`, one type per dimension, `Dimension1`, ...; the question's type; the person procedures imported from `profiles`; the person process, `person/6`, one clause per person declaration, in the order of the source, then the closed stream's, each drawing from the process's seed a value of 1..2147483646, `random(Seed?, 2147483646, K, S)`, handing `K?` to the person goal as its seed and going on with `S?`, so that the goal's draws and the process's are on different seed chains (sGLP 9f57a43, Definition "Person Process, Simulation Program, Stochastic Agent" and Appendix B, "Seeds"; sGLP's task 4 of 2026-10-09 20:59 UTC, where it handed its next seed `S?` to both); one answer procedure per interactive type, `answer_1`, ..., in the order of the interface, which assigns the program's answer once it is ground and logs it; the run declaration as `declaration/N`, its agents, horizon, seed and thresholds; `stochastic_person(B, T1, ..., Profiles, S)`, an agent's profiles drawn in order from the start `B` of its block, the seed `S` they leave its person process's (Appendix B); and each dimension's draw, `D(K, T1, ..., Q)`, the I-th profile for a draw of 1..100 above the threshold before it and up to its own, the thresholds the cumulative percentages of the profiles but the last.
  3. The person process selects a question by its term's functor, the one alternative of its interactive type, and passes the interactive type, the question's constant, on to the log: the questions are of the union of the interactive types, whose functors are distinct (TGLP, "Type Declarations"), which the checks require; and a constant `'Menu'`, starting with an upper-case letter, prints as `Menu`, a variable, GLP having no string operation to quote it.
  4. A line is a term as `send_to_user/1` prints it: a term on one line, an operator's term in prefix form, `'=<'(K?, 98)`; `:-`, `|`, `,`, `.`, `#` and a declaration's parentheses on lines of their own; a type `T?` as `T` and `?` on two lines, but for a primitive or predefined type, `Integer?`, whose text is one.  GLP has no string concatenation, so a line is never two terms (as Jurix's compiler prints a display a token to a line).  A constant of the source is printed as its name, so the source's constants are those GLP reads unquoted, as the examples' are.
  5. The checks (Section 3, "A population is well formed when ..."): the profiles of each dimension declare the same types, the dimensions' types are disjoint and cover the interactive types, each person procedure has the type its declaration requires, and each dimension's probabilities sum to one; and what the printing needs: one run declaration of a positive number of agents, a horizon in a unit of `span/2` and a seed; at most nine dimensions, named apart and not as a procedure of the population, each of one to nine profiles in whole percentages, the draw being of 1..100, at most nine thresholds in all; each profile in exactly one dimension; each person declaration in a profile, of an interactive type, once in its profile; each interactive type one compound alternative of one to nine arguments, an answer among them, their functors distinct, at most nine; each rated goal of a declared procedure that no goal calls unrated and that is no person procedure; each procedure declared once; and names left for the monitor's reference and the tokens.
  6. The harness's `run/6` and `run/7` stay written by hand, the machine's setup; they call `population # stochastic_person/5` and `population # person/6`, and `programs/sglp/self.glp` names the dimensions' types `Approach`, `Response`, `Spending` and `Credit` for the draws' reports, and each example's `self.glp` `Profiles`, `Interactive` and `Question` for its harness's imports: structurally the types `population.glp` prints, which the checker holds them to.
  7. `run.sh`'s default mix, 60 and 70 for the social graph and 50 and 50 for coins among friends, is the run declaration's, written in the script for the draw it computes before the run; `social_graph/4` reads the run declaration's from `declaration/6`.
  8. The printed modules are committed, the translated form in the repository that Section 4 names; `transform.sh --check` and test (x) hold them to what the transformation prints.
